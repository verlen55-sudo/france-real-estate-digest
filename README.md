# Дайджест недвижимости Франции

Программа раз в неделю (по понедельникам утром) собирает новости за последние 7 дней и присылает одно письмо на почту с тремя разделами:

1. **Юридические новости о недвижимости во Франции** — законы, налоги, права арендаторов и покупателей.
2. **Рынок недвижимости Франции** — цены, тренды, статистика нотариусов.
3. **Монтон и Лазурный берег** — необязательный раздел. Если за неделю новостей про Монтон не было, раздел просто не появляется в письме (это нормально — значит, писать не о чём).

Письмо автоматически присылает бесплатный сервис GitHub Actions — после настройки это не требует ни денег, ни твоего участия каждую неделю.

## Какие источники новостей на самом деле используются

Это важно знать, поэтому пишу прямо.

- **Раздел 1 (юр. новости):** у сайта ANIL и раздела «Logement» на service-public.fr **нет настоящего RSS-фида** (у service-public.fr RSS отключили при обновлении сайта, у ANIL его никогда не было). Поэтому раздел собирается через **поиск Google News** по запросу «droit immobilier France» — это резервный, но надёжный вариант: Google News сам собирает новости с юридических и новостных сайтов по этой теме.
- **Раздел 2 (рынок):** у нотариусов (notaires.fr, statistiques.notaires.fr) тоже **нет RSS-фида со статистикой цен** — тот RSS, что есть на notaires.fr, это ответы на юридические вопросы (FAQ), а не новости рынка. Поэтому раздел тоже собирается через **поиск Google News** по запросу «prix immobilier France notaires». Из-за этого свежих новостей в этом разделе может не быть каждую неделю — отчёты о ценах у нотариусов выходят раз в квартал, а не каждую неделю. Если на неделе ничего не найдено, раздел просто не появится в письме.
- **Раздел 3 (Монтон):** использует Google News по запросу «Menton» — так и было задумано изначально, без резервных вариантов.

Если в будущем у ANIL или нотариусов появится настоящий RSS-фид — можно будет заменить ссылку в файле `digest.py` (переменные `LEGAL_FEED_URL` и `MARKET_FEED_URL` в начале файла) на прямой адрес.

## Что нужно сделать, чтобы всё заработало

Дальше — пошаговая инструкция. Выполнить нужно один раз, дальше письма будут приходить сами.

### Шаг 1. Создать пароль приложения в Gmail

Обычный пароль от почты для таких программ использовать нельзя — Google требует отдельный «пароль приложения».

1. Зайди на [аккаунт Google](https://myaccount.google.com/) → раздел **«Безопасность»**.
2. Убедись, что включена **«Двухэтапная аутентификация»** (без неё пароли приложений не работают — включи, если выключена).
3. В поиске по настройкам аккаунта введи **«Пароли приложений»** (или «App passwords») и открой этот раздел.
4. Придумай любое название (например, «Дайджест недвижимости») и нажми **«Создать»**.
5. Google покажет пароль из 16 букв — скопируй его и сохрани (он больше не покажется). Это и есть `GMAIL_APP_PASSWORD`.

### Шаг 2. Завести приватный репозиторий на GitHub и загрузить туда папку

1. Зайди на [github.com](https://github.com) и войди (или зарегистрируйся, если нет аккаунта).
2. Нажми **«New repository»** (зелёная кнопка или «+» в правом верхнем углу → «New repository»).
3. Укажи любое имя, например `france-real-estate-digest`, и выбери **Private** (приватный — чтобы код и настройки видел только ты).
4. Создай репозиторий (кнопка «Create repository»).
5. Самый простой способ загрузить файлы — через веб-интерфейс: открой созданный репозиторий → **«uploading an existing file»** (или «Add file» → «Upload files») → перетащи туда всю папку `Дайджест-недвижимости-Франции` (файлы `digest.py`, `requirements.txt`, `README.md` и папку `.github`) → нажми **«Commit changes»**.
   - Если привычнее работать через Git/командную строку — подойдёт обычный `git init`, `git add`, `git commit`, `git push`, но это не обязательно: загрузка через браузер работает точно так же.

### Шаг 3. Добавить секреты в настройках репозитория

Секреты — это способ передать программе пароль, не записывая его в код (чтобы его никто не увидел).

1. В репозитории на GitHub открой **Settings** (вкладка сверху).
2. Слева выбери **Secrets and variables → Actions**.
3. Нажми **«New repository secret»** и добавь по очереди три секрета:
   - `GMAIL_USER` — твой адрес почты Gmail, с которого будут отправляться письма.
   - `GMAIL_APP_PASSWORD` — тот 16-буквенный пароль приложения из шага 1.
   - `RECIPIENT_EMAIL` — адрес, на который присылать письма (можно указать `verlen55@gmail.com`).

### Шаг 4. Проверить вручную, что всё работает

1. В репозитории открой вкладку **Actions**.
2. Слева выбери workflow **«Еженедельный дайджест недвижимости Франции»**.
3. Нажми кнопку **«Run workflow»** (справа) → снова **«Run workflow»** в появившемся окне.
4. Подожди около минуты, обнови страницу — появится запуск. Нажми на него, чтобы увидеть, прошло ли всё без ошибок (зелёная галочка — успех, красный крест — ошибка, тогда можно открыть лог и посмотреть, что написано).
5. Если всё получилось — на почту `RECIPIENT_EMAIL` придёт письмо с дайджестом.

После этого программа будет сама запускаться каждый понедельник — ничего больше делать не нужно.

## Расписание

Письмо приходит по понедельникам около 8:00 утра по парижскому времени. Техническая деталь: GitHub Actions всегда считает время по Гринвичу (UTC), а Франция весной переходит на летнее время. Поэтому зимой письмо придёт около 7:00, а летом — около 8:00 по местному времени (разница в час, не страшно). Если хочешь изменить время, в файле `.github/workflows/digest.yml` нужно поменять строку `cron: "0 6 * * 1"` (первое число — минуты, второе — час по UTC).

## Как проверить работу без отправки письма

Если нужно проверить, что новости собираются правильно, не отправляя письмо себе на почту:

```
pip install -r requirements.txt
python digest.py --dry-run
```

Текст письма выведется в консоль, отправки не будет.

## Файлы в проекте

- `digest.py` — сама программа.
- `requirements.txt` — список нужных библиотек Python (библиотека `feedparser` для чтения RSS).
- `.github/workflows/digest.yml` — настройка автоматического запуска раз в неделю через GitHub Actions.
- `README.md` — этот файл.
